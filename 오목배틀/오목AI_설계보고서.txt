 오목 AI 설계 보고서

[요약]
 자료구조에서 배운 "게임 트리 + 최대최소(minimax) 탐색"을 기반으로,
 위협 패턴 인식 + 알파-베타 가지치기 + 흑 금수 회피를 결합한 오목 AI다.
 핵심 두뇌는 ec_best() 함수이고, 심판이 부르는 공개 함수
 (BlackAttack/BlackDefence/WhiteAttack/WhiteDefence)는 얇은 래퍼다.


----------------------------------------------------------------
1. 보드 표현과 좌표
----------------------------------------------------------------
 - 내부 보드: board[row][col], 19x19
     0 = 빈칸, 1 = 흑, 2 = 백
 - 심판은 (x, y)로 좌표를 주고받는데 x=열(col), y=행(row)이다.
   따라서 내부 저장은 board[y][x]로 맞췄다.
 - 착수 범위는 0~17로 제한한다.
   (심판 EndGame이 0~17 범위만 승리로 인정하기 때문)


----------------------------------------------------------------
2. 규칙 인코딩 (심판과 동일)
----------------------------------------------------------------
 - 정확히 5목  = 승리
 - 6목 이상(장목) = 패배  (흑/백 모두)
 - 흑은 추가로 3-3, 4-4 = 반칙패
 => 백이 구조적으로 유리(3-3/4-4를 자유롭게 쓸 수 있음).
    AI는 흑일 때 위 금수를 스스로 피한다.


----------------------------------------------------------------
3. 위협 패턴 분석  (ec_dir, ec_features)
----------------------------------------------------------------
 어떤 칸에 돌을 두었을 때 무엇이 만들어지는지 분석한다.
 한 방향마다 중심 기준 11칸을 문자열로 만든다.
     M = 내 돌,  E = 빈칸,  B = 막힘(상대 돌/벽)

 찾는 패턴:
     EMMMME  -> 열린4 (다음 수에 무조건 5목, 막을 수 없음)
      MMMM.  -> 4    (다음 수에 5목 완성 가능)
      EMMME  -> 열린3 (다음 수에 열린4로 키울 수 있음)

 4방향(가로, 세로, 대각선 2개)을 모두 검사하여
 한 수의 특성을 뽑아낸다:
     { 5목 완성?, 장목?, 4의 개수, 열린4 개수, 열린3 개수 }

 흑 금수 판정(ec_black_forbidden):
     장목(6목) 이거나, 4가 2개 이상(4-4) 이거나,
     열린3이 2개 이상(3-3) 이면 금수.
     단, 5목 완성 수는 금수와 무관하게 항상 승리로 인정.


----------------------------------------------------------------
4. 한 수의 가치 점수  (ec_move_score) - 우선순위 사다리
----------------------------------------------------------------
     즉시 5목          -> 10,000,000
     열린4             ->  1,000,000   (다음 수 필승)
     4-4 (백만 가능)    ->    900,000
     4 + 열린3          ->    800,000   (양수겸장, 못 막음)
     열린3 두 개        ->    700,000
     단일 4             ->     50,000
     단일 열린3         ->      8,000
     그 외             ->  패턴 가중 합

 흑이면 금수(3-3/4-4/장목)에 해당하는 수는 -1로 깎아 회피.


----------------------------------------------------------------
5. 판 전체 평가함수  (ec_eval, ec_color_score)  ★성능의 핵심
----------------------------------------------------------------
 탐색의 끝(말단)에서 "지금 판이 누구에게 유리한가"를 점수로 매긴다.
 연속 돌의 정확한 길이 + 양 끝의 열림 여부를 본다.

     열린4 (_OOOO_) = 100,000      막힌4 = 12,000
     열린3          =   6,000      막힌3 =    600
     열린2          =     250      막힌2 =     30

 최종 = (내 점수) - (상대 점수) x 1.1   (수비를 약간 더 중시)

 [설계 노트]
 처음에는 "연속된 5칸 안에 내 돌이 몇 개"인 단순 방식이었는데,
 이는 열림/막힘을 구분하지 못해 강하지 못했다.
 위처럼 "정확한 길이 + 열린 끝" 방식으로 바꾸자
 같은 친구 AI 상대 전적이 5승5패에서 19승1패로 바뀌었다.
 즉, 탐색 깊이보다 "끝수 평가의 정확도"가 강함을 좌우했다.


----------------------------------------------------------------
6. 게임 트리 탐색  (ec_search) - 최대최소 + 알파베타
----------------------------------------------------------------
 자료구조에서 배운 최대최소 트리(minimax)를 negamax 형태로 구현.
 - 내 차례: 점수 최대화 / 상대 차례: 최소화
 - 알파-베타 가지치기로 불필요한 가지를 잘라 속도를 높인다.
 - 후보 수는 기존 돌 주변 2칸 이내(ec_gen)만 생성하고,
   ec_move_score로 정렬하여 상위 16개만 탐색한다.
   (19x19 전체를 깊게 보면 500ms 안에 못 끝냄)
 - 반복 심화(iterative deepening): 깊이 2 -> 4 -> 6 ...
   시간(약 400ms)이 다 되면 그때까지 찾은 최선의 수를 반환한다.
   => 시간 초과로 지는 일이 없다.


----------------------------------------------------------------
7. 최종 결정 파이프라인  (ec_best)
----------------------------------------------------------------
 실제로 둘 자리를 정하는 순서:
     1) 내가 지금 5목을 만들 수 있으면 -> 둔다 (즉시 승)
     2) 상대가 다음 수에 5목이면      -> 막는다
        (흑이면 금수 아닌 차단을 우선)
     3) 알파-베타 게임트리 탐색으로 최선의 수 계산
     4) (흑) 고른 수가 금수면 -> 금수가 아닌 최선의 수로 교체 (안전망)
 빈 보드면 중앙(9,9)에 둔다.


----------------------------------------------------------------
8. 심판 연결 (공개 함수)
----------------------------------------------------------------
     BlackAttack_2023184027(int* x, int* y)
         -> ec_best로 좌표 계산, *x=열 *y=행 으로 변환해 반환,
            내부 보드에 흑 기록
     BlackDefence_2023184027(int x, int y)
         -> 상대(백)가 둔 자리를 내부 보드에 기록
     WhiteAttack / WhiteDefence : 흑백만 바뀐 동일 구조

 시간 예산: OMOCK_BUDGET_MS = 400 (ms)
     심판 제한 500ms보다 안전하게 잡음. 실측 1수 최대 약 401ms.


----------------------------------------------------------------
9. 전체 흐름 한눈에
----------------------------------------------------------------
     심판이 "둬!" 호출
       -> ec_best
            -> 즉시 승 / 즉시 방어 체크
            -> 게임트리 탐색 (minimax + 알파베타, 400ms)
                 -> 후보를 ec_move_score로 정렬
                 -> 끝수를 ec_eval로 평가
            -> (흑) 금수 안전망
       -> (열,행) 좌표 반환


----------------------------------------------------------------
10. 테스트 결과
----------------------------------------------------------------
 자체 제작한 자동 대국 프로그램(심판 규칙 동일 적용)으로 검증:
     vs 랜덤 봇       : 흑/백 모두 전승
     vs 그리디 봇     : 흑/백 모두 전승, 자기 반칙/불법수 0
     vs 친구 AI(negamax 기반, 2023184014)
         - 평가함수 개선 전 : 5승 5패 (대등)
         - 평가함수 개선 후 : 19승 1패 (압도)
     1수 최대 소요 시간 : 약 401ms (500ms 제한 안전)


----------------------------------------------------------------
11. 핵심 설계 포인트 3가지 (보고서 요약용)
----------------------------------------------------------------
 (1) 위협 패턴 인식 : 열린4 / 4 / 열린3 등을 방향별 문자열로 탐지
 (2) 게임 트리 + 최대최소 탐색 : 알파-베타 가지치기로 깊이 확보
 (3) 흑 금수 회피 : 3-3 / 4-4 / 장목을 3중 안전망으로 차단
